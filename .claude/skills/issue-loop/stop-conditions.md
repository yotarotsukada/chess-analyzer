# 止まる条件（D99）

issue-loop と implementer が共有する。次のどれかに当たったら、推測で進めずに止まり、理由と選択肢をまとめる。

1. 台帳（`docs/decisions.md`）や ADR と矛盾する変更が要る
2. 利用者に見える方針、データ、費用に関わる曖昧さがある
3. 秘密情報、外部アカウント、課金、手作業の操作が要る
4. テストを消す・skip する・根拠なく期待値を変えないと通らない
5. ユーザーの確認が要るファイル（ADR・台帳・fly.toml・レビューの観点・Hooks）を変える必要がある
6. Issue のスコープを超える変更が要る（見つけたものは「別 Issue の候補」として書くだけにする）
7. 修正が2回で収束しない（issue-loop が判定する）
8. 本番の確認が失敗した（issue-loop が判定する）

後から戻せる小さな曖昧さは、控えめな解釈で進め、「気になる点」に書く。
