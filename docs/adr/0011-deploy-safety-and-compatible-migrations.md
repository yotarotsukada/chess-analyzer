# 自動デプロイの安全網と、後方互換のマイグレーション

マージが人を待たずに本番へ出る（ADR 0009、D118）ので、壊れたときに自動で戻せることを前提にする。Fly のデプロイには、失敗したときに自動で前の版へ戻す仕組みがない（2026-10 時点で確認できた範囲）ので、自前で用意する。

- ヘルスチェックを2つに分ける。Fly が常に叩くチェックは DB に触れない（触れると Neon の自動休止が効かなくなる。D51）。DB まで見るチェックは、デプロイ後のスモークテストでだけ使う。
- GitHub Actions のデプロイの後に、トップページ、DB まで見るチェック、本番に用意した見本の Game Review を読み取りで確かめる。失敗したら直前のイメージに戻し、incident の Issue を開く。revert PR は、次に指示を受けたときにローカルのセッションが作る。
- DB のマイグレーションは、後方互換（expand / contract）の変更に限る。イメージを戻しても DB は戻らないので、新旧のアプリが同じ DB で動ける必要がある。

## Consequences

- 列の削除や名前の変更は、「足す → 移す → 消す」の複数の PR に分ける。エージェントのレビューで確かめる。
- 本番で対局を作る確認はしない（回数制限とデータを汚さないため）。
- マイグレーションを含むマージは revert せず、イメージを戻すだけにして人の判断を待つ。incident の Issue が開いている間は、ループで新しい変更をマージしない。
