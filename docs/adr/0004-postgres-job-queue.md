# ジョブキューは Postgres（pg-boss）で実装する

解析ジョブのキューは、専用のメッセージブローカー（Redis/BullMQ、SQS など）を使わず、アプリのデータベースと同じ Postgres（Neon）上に pg-boss で実装する。

理由は次の3つ。

- 個人開発なので、運用するインフラを1つでも減らしたい。
- Game、Analysis、ジョブを同じトランザクションで扱える。
- 処理量は、Worker 1台の処理能力（1日に最大で数百局）を超えない。

## Consequences

- Worker は常駐して長時間接続するプロセスなので、Neon のプーラーを通さずに直接接続する。
- キューの状態を定期的に確認すると、Neon の自動休止が働かなくなり、無料枠の計算時間を使い切るおそれがある。キューの確認は、リクエストをきっかけに行う。
- 処理量が桁違いに増えたら、そのときに移行を検討する。
