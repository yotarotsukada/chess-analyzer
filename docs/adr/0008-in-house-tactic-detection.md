# 戦術の判定は chess.js の上に自作する

両取り、ピン、取られっぱなしの駒などの戦術パターンの判定は、chess.js（BSD-2-Clause）の上に自作する。lichess-puzzler の tagger（AGPL-3.0）や chessops（GPL-3.0）は、使いもせず、移植もしない。

これらは戦術判定の手本として真っ先に名前が挙がる。それでも使わない理由は、ライセンスごとに異なる。

- chessops（GPL）：判定のコードは app/domain に置くので、クライアントのバンドルにも入りうる。ブラウザに配れば頒布にあたる。
- lichess-puzzler（AGPL）：サーバーでしか使わなくても、ネットワーク越しに使わせればソースの提供義務が生じる。Python で書かれており、python-chess（GPL）にも依存している。

どちらも、このリポジトリを MIT で提供する方針と両立しない（ADR 0003 と同じ考え方）。加えて、lichess-puzzler の tagger は手順が一本道のパズルを前提にしており、実戦の局面とエンジンが読んだ手順にはそのまま使えない。MIT や BSD で使える定番の JS ライブラリは見つからなかった（docs/research/explanations.md）。

参考にしてよいのは考え方まで（例：「フォークとは、1つの駒が価値のある駒を2つ以上攻めること」）。コードを写したり、別の言語に訳したりしない。

## Consequences

- パターン名は、エンジンの手順をたどって実際に駒得を確かめられたときだけ付ける（D67）。盤面だけを見た判定は誤検出が多いので、そこで止めない。
- コードは AI エージェントが書くので、この方針をエージェント向けの指示にも書く。
- Stockfish は別プロセスとして UCI で通信しているので、この ADR の対象外（ADR 0001、0003）。
